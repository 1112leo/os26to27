# 행사 웹사이트

GitHub Pages + Firebase. HTML·CSS·JavaScript를 직접 수정합니다. 설치·빌드 과정은 없습니다.

- `typing/`: 타자 대회. 관리자 `/typing/admin/`.
- `write/`: 글 작성. 관리자 `/write/admin/`.
- `welcome/`: 승인 글 조회. 관리자 `/welcome/admin/`.

루트 `/`에는 페이지가 없습니다. 공통 파일은 루트에 둡니다.

| 파일                                                         | 용도                     |
| ------------------------------------------------------------ | ------------------------ |
| `firebase.js`                                                | Firebase 연결·인증       |
| `database.js`                                                | DB 작업·검증·내보내기    |
| `common.js`                                                  | 입력 검증·파일·공통 함수 |
| `admin.js`                                                   | 관리자 화면              |
| `login.js`                                                   | 학생 입장·관리자 로그인  |
| `style.css`                                                  | 기본 스타일              |
| `firebase-config.json`                                       | 공개 웹 SDK 설정         |
| `firestore.rules`, `firestore.indexes.json`, `firebase.json` | DB 규칙·배포 설정        |

로컬 실행: Node 24 이상에서 `node serve.mjs`. `http://127.0.0.1:5176/write/` 또는 `/typing/`으로 접속합니다. 에뮬레이터 검증 시 해당 주소에 `?emulator=1`을 붙입니다. 이 옵션은 로컬 주소에서만 작동합니다.

관리자 이메일·비밀번호로 로그인한 뒤 글·기록 추가/수정/삭제, 접수 설정, 문구 변경, 공개 승인, 계정과 권한 관리를 처리합니다. 공개된 글은 별도 재배포 없이 갱신됩니다. 문구 본문 변경은 새 버전으로 저장해 이전 기록의 채점 기준을 유지합니다.

타자는 학번(숫자 4~10자리)·이름으로 입장합니다. 별도 학생 회원가입이나 비밀번호는 없으며, 정보는 해당 탭의 세션에 보관하고 로그아웃 시 비웁니다. 기록에 학번·이름을 저장하며, 기존 데이터와 호환되도록 저장 필드는 `participantId`·`displayName`을 유지합니다. 학생 입장은 본인 인증이나 관리자 권한을 부여하지 않습니다. 로그인 화면의 관리자 탭은 Firebase 계정과 관리자 권한을 확인한 뒤 관리 화면으로 이동합니다. 글 작성은 기존 익명 방식을 유지합니다.

모든 관리자 화면 상단에서 타자·글·공개 글 관리로 이동할 수 있습니다. 공개 글 관리는 글 관리와 같은 데이터를 사용하며, 승인된 글을 먼저 표시합니다.

GitHub Pages는 `main` 브랜치의 루트를 직접 배포합니다. 푸시하면 자동 반영됩니다. 다른 저장소로 옮길 때는 이 파일들과 세 폴더를 복사하고, 대상 Firebase 프로젝트의 공개 SDK 설정과 보안 규칙을 연결합니다. `firebase-config.json`은 공개되는 클라이언트 설정입니다. 관리자 비밀번호·서비스 계정 키는 넣지 않습니다.

이전 시 확인할 설정:

- `CNAME`은 현재 임시 배포 전용입니다. 새 저장소에서는 복사하지 않거나 새 도메인으로 바꿉니다. GitHub Pages도 새 저장소에서 활성화합니다.
- 같은 Firebase 프로젝트를 계속 쓰면 `firebase-config.json`은 그대로 사용합니다. Firebase 프로젝트까지 바꿀 때만 이 파일을 교체하고 DB 규칙·인덱스·관리자 권한을 새 프로젝트에 설정합니다.
- 새 사이트 호스트는 Firebase Authentication의 승인된 도메인에 등록합니다. 이 설정은 `firebase.json` 배포로 등록되지 않습니다. 익명 인증과 이메일/비밀번호 인증도 Firebase 콘솔에서 활성화합니다.
- 경로는 현재 파일 위치를 기준으로 계산하므로 커스텀 도메인 루트와 GitHub Pages의 `/저장소명/` 경로에서 같은 소스를 사용합니다. `/typing/`, `/write/`, `/welcome/`와 공통 파일의 상대적인 구조는 유지합니다.
- 비밀번호 재설정은 Firebase 기본 이메일 링크 화면을 사용합니다. 복귀 주소는 현재 사이트 경로에서 계산합니다.

로그인 화면에서 이메일 입력 후 ‘비밀번호 재설정’을 누르면 메일을 보냅니다. 메일의 링크를 열어 새 비밀번호를 설정합니다. 별도 SMTP 계정이나 서버 함수는 사용하지 않습니다.

테스트·이전 소스·설치 파일·로그는 프로젝트 밖의 개발 보관 폴더에 둡니다.
