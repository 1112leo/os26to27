# 행사 웹사이트

GitHub Pages + Firebase. 학생 화면은 HTML·CSS·JavaScript를 직접 수정하며 설치·빌드 과정이 없습니다.

- `typing/`: 학생 타자 대회. 관리자 `/typing/admin/`.
- `write/`: 학생 글 작성. 관리자 `/write/admin/`.
- `welcome/`: 승인된 공개 글 조회. 로그인 불필요. 관리자 `/welcome/admin/`.
- `scripts/`: 비공개 명부를 읽는 일괄 등록 도구와 선택적 계정 관리 서버 소스. 명부 자체는 포함하지 않습니다.

루트 `/`에는 페이지가 없습니다. 공통 파일은 루트에 둡니다.

| 파일                                                         | 용도                                                    |
| ------------------------------------------------------------ | ------------------------------------------------------- |
| `firebase.js`                                                | 학생·관리자 인증, Firebase 연결, 세션 정책              |
| `login.js`                                                   | 학번·비밀번호 통합 로그인(관리자 이메일도 처리)         |
| `database.js`                                                | 글·타자 접수, 검증, 검수·공개, 내보내기                 |
| `admin.js`, `students.js`                                    | 관리자 화면과 학생 검색·제한·관리 기록                  |
| `common.js`, `style.css`                                     | 공통 함수·스타일                                        |
| `firebase-config.json`                                       | 공개 웹 SDK 설정                                        |
| `firestore.rules`, `firestore.indexes.json`, `firebase.json` | 보안 규칙·인덱스·배포 설정                              |
| `scripts/import-students.mjs`                                | 서버 Admin SDK를 사용하는 멱등 학생 일괄 등록           |
| `scripts/functions/`                                         | 관리자 전용 비밀번호 재발급 서버. 운영 연결은 현재 보류 |

로컬 실행: Node 24 이상에서 `node serve.mjs`. `/typing/`, `/write/`, `/welcome/`으로 접속합니다. `?emulator=1`은 localhost 또는 127.0.0.1에서만 에뮬레이터에 연결하며 기기 보호 정책을 바꾸지 않습니다.

학생 ID는 입학 당시 학번 7자리입니다. 내부 Auth 이메일은 `<학번>@students.<Firebase projectId>.invalid`, UID는 학번이며 이메일은 학생 화면에 표시하지 않습니다. 초기 비밀번호는 최초 계정 생성 시 학번으로 설정합니다. 별도 회원가입이나 최초 변경 강제는 없습니다. ID·초기 비밀번호가 같으므로 계정 기록만으로 실제 작성자를 확정하지 않습니다. Firestore에는 비밀번호나 비밀번호 해시를 저장하지 않습니다.

학생 로그인은 Firebase 인증과 `students/{uid}` 명부의 활성 상태를 확인합니다. 이름은 명부에서 읽습니다. 관리자 이메일은 기존 `admins/{uid}.enabled` 권한을 확인한 뒤 해당 기능의 관리자 화면으로 이동합니다. 학생 로그인 시 이전 관리자 세션은 종료합니다. 예전의 학번·이름 입력 세션과 익명 계정은 새 제출에 사용할 수 없습니다.

글과 타자 기록의 `owner_uid`는 인증 계정이며 타자 `participantId`·`displayName`은 명부의 학번·이름과 일치해야 합니다. 새 글은 승인 대기 상태입니다. 공개 글에는 기존 공개용 본문·별명만 포함하며 학생 명부와 관리 기록은 공개하지 않습니다. 기존 글·타자 기록을 지우거나 새 학생 계정에 자동 귀속하지 않습니다.

관리자 학생 탭에서 학번·이름·학년으로 검색하고 작성 제한, 기간 제한, 계정 활성 상태, 작성 글, 관리 기록을 확인합니다. 작성 제한은 글에만 적용하고, 비활성 계정은 학생 제출 전체를 거부합니다. 상태 변경은 사유와 불변 관리 기록을 같은 배치로 저장합니다. 현재 학년은 운영 설정의 기준 학년도와 고정 입학년도로 계산하고, 입학 학번으로 현재 반·번호를 추정하지 않습니다.

`settings/sessionPolicy`는 관리자 설정에서 관리합니다. 없으면 공용 기기 모드·미사용 10분·2026학년도를 적용합니다. 공용 기기는 메모리 인증만 사용하고 글 제출 후 자동 로그아웃합니다. 개인 기기는 브라우저 탭 세션을 유지합니다. 정책은 URL로 해제할 수 없습니다. 타자 진행·저장 중에는 미사용 로그아웃을 미룹니다. 저장 실패 기록은 기기 백업에 남기고 로그아웃 시 학생 화면을 비웁니다. 기기 백업은 관리자 화면에서만 조회·재전송하며 다음 학생에게 이전 결과를 표시하지 않습니다.

모든 타자 시도는 보관합니다. 문구 버전·연습/공식별 학번당 최고 기록 하나에 순위를 매기며 점수 → 오타 → 소요 시간으로 비교합니다. 완전 동점인 같은 학생의 시도는 먼저 완료한 것을 대표로 선택합니다. 제외 기록은 순위에 반영하지 않습니다. 관리자 보기에서 최고 기록·전체 시도를 전환하고 CSV도 선택한 보기를 따릅니다. 전체 JSON은 모든 기록을 보관합니다. 시작·중단·다시 하기 버튼은 없습니다. 로그인 후 문구를 불러오면 첫 입력부터 측정합니다. 분당 타수는 글자 수가 아니라 두벌식 키 입력 수를 기준으로 계산합니다.

학생 일괄 등록은 공개 웹사이트에서 실행하지 않습니다. `firebase-admin`은 별도 개발 환경에 설치하고, 명부·자격 증명·결과 보고서는 저장소 밖에 둡니다. 도구는 입력 전체의 중복·형식·관리자 충돌을 검사하고 기본값으로 읽기 전용 검증을 수행합니다.

```text
node scripts/import-students.mjs --input PRIVATE_ROSTER.json --project PROJECT_ID --dry-run --admin-module-dir EXTERNAL_NODE_MODULES --report PRIVATE_REPORT.json
```

검토한 명부에 `--apply`를 명시해야 계정을 생성합니다. `--only 학번`으로 개별 재시도할 수 있으며 `--concurrency`는 기본 5, 범위 1~10입니다. Auth 생성 후 Firestore 생성이 실패한 경우 다음 실행에서 학생 문서만 복구합니다. 기존 계정 비밀번호·제재 상태·관리자 계정은 변경하지 않습니다. 기본 인증은 Admin SDK의 Application Default Credentials이며, `--credential-module`로 저장소 밖의 자격 증명 모듈을 지정할 수 있습니다. 보고서에는 진행·오류를 남기고 비밀번호는 기록하지 않습니다.

기존 관리자 비밀번호 재설정은 Firebase 기본 이메일 링크를 사용합니다. 학생 비밀번호 재발급은 서버 Admin SDK가 필요합니다. `scripts/functions`는 관리자 권한을 확인하고 임시 비밀번호를 한 번만 반환하며 비밀번호를 로그·Firestore에 남기지 않습니다. 현재 무료 요금제 유지 방침에 따라 운영 배포는 보류했고 `studentAdminFunctionsEnabled`를 활성화하지 않습니다. 향후 서버 배포가 완료된 경우에만 이 공개 설정을 `true`로 바꿉니다. Functions 지역을 바꾸면 서버 `STUDENT_FUNCTION_REGION`과 클라이언트 `functionsRegion`을 같이 설정합니다. 학생 상태 관리에는 서버 함수가 필요하지 않습니다.

GitHub Pages는 `main` 브랜치 루트를 직접 배포하며 푸시하면 반영됩니다. 다른 레포·도메인으로 옮길 때 파일의 상대적인 구조를 유지하면 경로가 따라갑니다.

- `CNAME`은 임시 배포 전용이므로 새 저장소에서는 제거하거나 새 도메인으로 바꿉니다.
- 새 저장소의 Pages를 활성화하고 Firebase Authentication의 승인된 도메인에 새 호스트를 등록합니다.
- 같은 Firebase 프로젝트를 사용하면 기존 Auth 계정·DB·SDK 설정을 그대로 유지합니다. 다른 Firebase 프로젝트로 바꾸는 경우 Auth·DB 이전과 공개 SDK 설정 교체가 별도로 필요합니다.
- 보안 규칙은 대상 Firebase에 배포해야 적용됩니다. 익명 인증의 활성 여부와 관계없이 새 학생 제출은 규칙에서 차단합니다.

전체 명부, 검토 보고서, 자격 증명, 테스트, 설치 파일, 로그는 공개 저장소에 포함하지 않습니다.
