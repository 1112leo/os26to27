- Firestore 에뮬레이터 테스트 20개: 원자적 접수·접수증 재사용·개인정보 조회 차단·직접 위조 요청·관리자 권한·행사 마감·요청 제한·점수 산식과 반올림·검수·상품 권한·마감 후 운영진 미전송 기록 복구·1,505건 전체 조회·빈 대상 백업 복구·권한 규칙 아래 전체 백업 생성.
- TypeScript 검사와 GitHub Pages 경로를 적용한 프로덕션 빌드.
- 브라우저에서 로컬 Auth/Firestore 에뮬레이터를 사용해 편지 입력 → 접수번호 확인 → 관리자 로그인 → 공개용 본문 승인 → 원문 보존 확인.
- 브라우저에서 타자 문구 완성 → 서버 저장 완료 → 운영진 통합 기록 조회 → 운영진 확인 → 연습 상품 지급 차단 → 로그아웃 후 기록 조회 차단.
- 공개 JSON 내보내기 버튼과 `/os26to27/welcome` QR 생성.
- 브라우저용 운영 의존성 `npm audit --omit=dev`: 취약점 0건.

- 추가로 브라우저에서 실제 `os20th` Firestore 편지 접수, 접수번호 발급, 이메일/비밀번호 관리자 로그인, 원문 조회 및 공개 제외 검수를 확인했습니다. 실제 DB 검증용 테스트 글은 공개 제외 상태로 남겼습니다.
- GitHub Pages 공개 주소에서도 편지 접수와 타자 완료 → 서버 저장 → 운영진 로그인을 확인했습니다. 실제 Firestore의 서버 접수 시간과 문구·연습·상품 미수령·확인 대기 필드를 읽어 저장을 확인했습니다. 인증하지 않은 웹 SDK의 원문 읽기는 `permission-denied`로 거절됐습니다.
- 실서버 백업 검사에서 발견한 `settings` 컬렉션 목록 권한 오류는 공개 행사 설정인 `settings/event` 단건 조회로 수정했습니다. 같은 보안 규칙을 적용한 백업 회귀 테스트를 추가했습니다.

에뮬레이터는 실제 Firebase가 제공하는 로컬 시험 도구입니다. 자동 입력 브라우저 시험은 실제 물리 PC 두벌식 IME 시험을 대체하지 않습니다. 행사 전 실제 운영 PC에서 한글 조합·백스페이스·공용 IP 참가량·네트워크 장애와 Firebase 할당량을 확인하세요.

기존 Cloudflare 사이트와 원격 D1 자료를 수정·이전·삭제하지 않았습니다. 기존 도메인의 IndexedDB 자료는 새 도메인에서 자동으로 접근할 수 없습니다.
