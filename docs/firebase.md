# GitHub Pages + Firebase 시험 버전

2026-10-27. 기존 Cloudflare 프로덕션과 별개인 구현입니다. Firebase 계정 연결 및 실제 프로젝트 생성은 소유자 인증 후 진행해야 합니다. 이 문서는 연결이 완료됐다는 증빙이 아닙니다.

## 데이터와 권한

| 컬렉션 | 읽기 | 쓰기 |
| --- | --- | --- |
| `letters` | 운영진만 | 익명 기기의 원자적 신규 접수, 운영진 검수 필드 수정 |
| `typingResults` | 운영진만 | 원자적 신규 접수, 운영진 확인·제외·상품 상태 수정 |
| `receipts` | 해당 기기 단건, 운영진 | 신규 접수 트랜잭션에서 생성만 |
| `rateLimits` | 해당 기기 단건 | 서버 시간·증가 횟수·새 접수증 검증을 거친 변경만 |
| `admins` | 자기 문서 단건 | 클라이언트 쓰기 금지 |
| `settings/event` | 공개 | 운영진만 |
| `challenges` | 공개 | 운영진만 |

모든 기타 경로는 차단합니다. 공개 신입생 화면은 Firestore 원문을 조회하지 않고 `public/data/welcome.json`만 읽습니다. 기기 접수증에는 이름·본문 대신 접수 ID, 종류, 소유 UID, SHA-256, 서버 시간이 들어갑니다. 기기가 자기 원문도 다시 읽지 못하도록 하여 공용 PC에서 과거 글이 노출되는 것을 막습니다.

익명 Auth는 참가자 개인 계정이 아닌 **브라우저 기기 식별자**로 재사용합니다. 운영진 Auth는 별도 Firebase 앱과 세션 저장소를 사용하여 관리자 로그인으로 기기 익명 계정이 바뀌지 않습니다. 탭을 닫으면 운영진 세션이 종료되고, 운영 중에는 로그아웃 버튼을 사용합니다. 역할을 회수하면 새 DB 요청은 규칙에서 즉시 차단됩니다.

서버 타임스탬프·본문 길이·필수 동의·문구 버전·점수 산식·최저 0점·초기 미확인 상태를 보안 규칙에서 다시 검사합니다. 브라우저가 보내는 소요 시간의 진실성까지 증명하지는 못합니다. 공식 대회는 운영진 확인과 실제 PC 한글 IME 입력 시험 후 열어야 합니다. 임시 애국가는 연습 전용입니다.

## 1,000~2,000건 규모와 무료 한도

Firestore 무료 기본 한도는 저장 1 GiB, 읽기 50,000/일, 쓰기 20,000/일, 삭제 20,000/일입니다. 접수 한 건이 기록·접수증·기기 카운터의 **3회 쓰기**이므로 1,500건은 4,500회 쓰기입니다. 검수·행사 설정·다른 접수와 합산해야 하며 보안 규칙의 종속 문서 읽기도 읽기량에 포함됩니다. 저장 건수만으로 한도를 판단하지 않습니다. 이 설계는 수천 건 규모 운영을 전제로 합니다.

운영진 목록은 DB에서 100건씩 페이지 조회한 뒤 해당 세션 메모리에서 검색·정렬합니다. 화면은 편지 20건, 타자 기록 50건씩 표시합니다. 편지 검색·필터 변경에는 30초 캐시를 사용합니다. 새로고침·백업·다른 기기의 조회는 추가 읽기를 소비합니다. 대규모 상시 서비스라면 서버 검색/쿼리 기반 페이지 구분으로 변경해야 합니다.

익명 계정 신규 생성에는 IP당 시간당 100개 제한이 있습니다. 학교 공용 IP에서 여러 개인 휴대전화가 처음 접속하면 영향을 받을 수 있습니다. 부스 PC의 기존 익명 계정은 재사용하며, 다수 개인 기기 참여 전에는 Firebase 콘솔의 가입 제한 조정과 실제 부하를 점검합니다. 기기당 분당 600회 규칙은 악의적인 계정 재발급을 막는 전역 방어가 아닙니다. 실제 행사 전 Auth/Firestore 사용량을 관찰하고 App Check 등 추가 보호를 검토합니다.

공식 참고: [Firestore 한도](https://firebase.google.com/docs/firestore/quotas), [Auth 제한](https://firebase.google.com/docs/auth/limits), [규칙의 원자적 쓰기 검증](https://firebase.google.com/docs/firestore/security/rules-conditions#access_other_documents).

## 실제 연결 체크

1. Firebase 소유자 인증, 프로젝트·웹 앱·Firestore 생성. 위치 선택 후 임의 변경 불가.
2. 익명 및 이메일/비밀번호 로그인 사용 설정.
3. 운영진 Auth 계정 생성, 해당 UID에만 `admins/{uid}.enabled=true`를 신뢰된 콘솔에서 등록.
4. `firebase deploy --project PROJECT --only firestore:rules,firestore:indexes`.
5. 공개 웹 설정 등록, GitHub Pages 도메인 `1112leo.github.io` 승인, Pages 브랜치 재배포.
6. 관리자 로그인 후 단계 A로 행사/문구 초기화. 기기 두 대에서 편지·타자 결과 저장 및 운영진 확인.
7. 단계 B에서 신규 접수 거절 및 저장 성공 응답이 없던 동일 접수 재확인. 공개 JSON 생성과 원문 비공개 확인.
8. 비공개 백업을 별도 빈 프로젝트/에뮬레이터에 복구해 건수·본문·서버 시간 비교.

서비스 계정 키, 관리자 비밀번호, Firebase CLI 갱신 토큰은 GitHub Actions 변수/저장소/채팅에 넣지 않습니다. `.firebaserc`는 기본으로 `demo-ohsung`을 가리켜 실수로 실제 리소스를 수정하지 않도록 했습니다. 실서비스 배포는 항상 `--project`를 명시합니다.

## 검증

단위 테스트는 IME 조합 확정·오타 누적·점수·동점·IndexedDB·CSV 및 공개 JSON 검증/복원을 확인합니다. Firebase 에뮬레이터 테스트는 실제 클라이언트 SDK와 보안 규칙을 사용하여 원자적 접수, 재시도, 원문 접근 차단, 직접 위조 요청, 역할 승격 차단, 접수 마감, 요청 제한, 점수 위조, 검수·상품 권한, 1,505건 조회 및 비공개 백업 복구를 확인합니다. 에뮬레이터 통과가 실서비스 계정·도메인·할당량 연결까지 보증하지는 않습니다.

실서비스 브라우저 의존성의 `npm audit --omit=dev`는 취약점 0건입니다. 개발용 Firebase CLI의 Pub/Sub → OpenTelemetry 1.x 전이 의존성에 moderate 경고가 남아 있습니다. 앱 번들에 포함되지 않으며 호환되지 않는 주 버전을 강제 교체하지 않았습니다. gRPC 보안 패치는 호환 가능한 1.14.6 override로 적용했습니다.
